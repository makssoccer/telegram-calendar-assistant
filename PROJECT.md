# Личный Telegram-ассистент — план MVP

## Цель

Сделать работающего Python-бота для одного пользователя: писать ему обычные сообщения, просматривать Google Calendar и создавать встречи после подтверждения.

Разработку ведём в этом репозитории с помощью Codex. Этот файл — основной ориентир: после выполнения этапа обновляем его статус и записываем следующий шаг.

Приоритет — минимально работоспособное приложение. Не добавляем отдельные этапы написания тестов, сложную инфраструктуру и абстракции ради будущих возможностей. Проверяем запуск и основные сценарии вручную. Не отмечаем интеграцию проверенной, если запуск с реальным сервисом не выполнялся.

## Поведение первой версии

- Бот работает только с владельцем в личном Telegram-чате; доступ проверяется по Telegram ID.
- `/start` и `/help` объясняют возможности; `/today` показывает события за сегодня.
- «Что у меня завтра?» возвращает события календаря за нужный день или период.
- «Добавь завтра в 15:00 встречу с Андреем на час» подготавливает встречу.
- Если не хватает времени или длительности, бот задаёт уточняющий вопрос.
- Перед записью показывает название, точную дату, начало, конец и часовой пояс, затем кнопки «Создать» и «Отмена».
- Нажатие «Создать» записывает сохранённые параметры в Google Calendar и возвращает результат со ссылкой, если она доступна.
- Повторное нажатие не создаёт второе событие.
- Ошибка внешнего сервиса не превращается в сообщение об успешном выполнении.

Часовой пояс по умолчанию — Europe/Minsk, с возможностью изменить настройку. Используется один настраиваемый календарь.

## Минимальный стек

- Python: совместимая поддерживаемая версия, фиксируем при создании проекта.
- uv: зависимости и запуск; версии фиксируются в uv.lock.
- aiogram: Telegram, long polling без публичного HTTP-сервера.
- Pydantic / pydantic-settings: аргументы инструментов и конфигурация.
- Google Calendar API и OAuth: доступ к личному календарю.
- SDK одного выбранного провайдера модели с tool calling.
- PostgreSQL: ожидающие подтверждения и результаты создания; данные сохраняются в именованном Docker volume.
- SQLAlchemy + asyncpg: доступ к БД; Alembic: миграции схемы.
- Dockerfile и Docker Compose: запуск приложения и PostgreSQL одной командой.
- Обычное логирование Python.

Провайдер: OpenRouter, бесплатный маршрутизатор openrouter/free. Платные модели запрещены настройками приложения; поддерживаются также явно указанные модели с суффиксом :free.

## Устройство приложения

Один процесс и несколько небольших модулей:

```text
app/
  __main__.py       # запуск и завершение
  config.py        # настройки
  telegram_bot.py  # сообщения, команды, кнопки, проверка владельца
  calendar.py      # OAuth и операции Google Calendar
  agent.py         # запросы модели и цикл инструментов
  tools.py         # описание и проверка инструментов
  storage.py       # PostgreSQL и ожидающие действия
```

Структуру можно уточнять по мере реализации. Не создаём универсальную платформу интеграций.

Цикл агента: сообщение → модель → проверка вызова инструмента → выполнение → результат модели → ответ пользователю. Ограничиваем количество шагов и время сетевых запросов.

Первые инструменты:

- `list_events(start, end)` — прочитать события за период.
- `prepare_event(title, start, end, description?)` — проверить и сохранить черновик для подтверждения.

Запись в календарь выполняет обработчик подтверждения. Модель не получает инструмент записи, позволяющий обходить подтверждение. Содержимое календаря — данные, а не инструкции агенту.

Контекст последних сообщений можно держать в памяти с ограничением размера. После перезапуска разговор начинается заново; подтверждения и результаты операций сохраняются в PostgreSQL.

### 1. Запускаемый Telegram-бот

Статус: приложение запущено в Docker; PostgreSQL и Telegram polling работают. Ожидается проверка /ping владельцем.

- Создать Python-проект, pyproject.toml, uv.lock и .gitignore.
- Добавить настройки, .env.example без секретов и краткий README запуска на Windows с Docker Desktop.
- Создать Dockerfile, .dockerignore и compose.yaml с сервисами приложения и PostgreSQL.
- Настроить volume БД, healthcheck PostgreSQL, подключение приложения и применение миграций Alembic перед запуском бота.
- Проверить запуск через docker compose up --build; остановка и пересоздание контейнеров должны сохранять данные.
- Подключить aiogram и long polling.
- Реализовать проверку владельца и команды `/start`, `/help`, `/ping`.
- Корректно закрывать сетевые сессии при остановке.

Готово, когда приложение и PostgreSQL запускаются через Docker Compose, подключение к БД работает, владелец получает `pong`, чужие пользователи и группы не получают доступ к функциям.

От пользователя потребуется токен бота и Telegram ID. Секреты вводятся в локальную конфигурацию, не в проектную документацию.

## Создание встреч — 02.10.2026

Реализованы prepare_event, проверка будущей даты, черновики в PostgreSQL и кнопки «Создать»/«Отмена». Запись выполняется только после подтверждения владельцем. ## Постоянная история — 05.10.2026

История хранится в PostgreSQL: последние четыре пары сообщений, до 16 000 символов JSON. Она загружается перед каждым запросом и сохраняется после перезапуска. Подготовка черновика, успешное создание и отмена записываются вместе с состоянием черновика в одной транзакции. Повторная обработка подтверждения не дублирует результат. Старые сообщения из оперативной памяти до обновления восстановить нельзя. /reset очищает сохранённую историю, но не удаляет встречи и черновики. После /reset новое нажатие кнопки существующего черновика добавит результат в новую историю. История используется для понимания разговора; актуальное расписание по-прежнему запрашивается у Google. Текст хранится в локальной БД и передаётся облачной модели при последующих запросах.
