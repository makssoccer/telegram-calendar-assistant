# Личный Telegram-ассистент

Добавлен туристический режим для Гродно: `/places`, `/walk 120`, `/walk 120 return`
и рассказы по источникам через существующий harness. Для реальных пеших переходов
нужен `ORS_API_KEY`, для рассказов — настроенный OpenRouter.
[Настройка и устройство туристического режима](docs/TOURISM.md).

Подробное [руководство пользователя](USER_GUIDE.md): команды, настройки, авторизация, запуск и решение проблем.

[Руководство по коду для разработчика без опыта Python](docs/PYTHON_PROJECT_GUIDE.md): аналогии с Java, структура, выполнение /today и внесение изменений.

Python-бот с PostgreSQL и Docker Compose. Реализованы `/start`, `/help`, `/ping`, `/today` и доступ только владельцу в личном чате. Для чтения Google Calendar требуется авторизация по [инструкции](docs/GOOGLE_CALENDAR.md). Подключён OpenRouter: обычные текстовые вопросы о расписании и /reset. Реализованы создание, перенос и удаление обычных встреч с подтверждением, история в PostgreSQL, напоминания и локальное распознавание голосовых. План — в [PROJECT.md](PROJECT.md).

## Запуск на Windows

1. Установите и запустите Docker Desktop с Linux containers. Проверьте `docker version` и `docker compose version` в PowerShell.
2. Создайте бота через [BotFather](https://t.me/BotFather), получите токен. Узнайте свой числовой Telegram ID (например, через `@userinfobot`; токен ему передавать не нужно).
3. В папке проекта создайте локальную конфигурацию:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

4. Заполните `TELEGRAM_BOT_TOKEN`, `OWNER_TELEGRAM_ID` и `POSTGRES_PASSWORD`. Для пароля БД удобно использовать случайную строку из букв и цифр. Не отправляйте токены в чат и не добавляйте `.env` в Git.
5. Запустите:

   ```powershell
   docker compose up --build -d
   docker compose logs -f bot
   ```

6. Напишите своему боту `/start`, затем `/ping`. Ожидаемый ответ: `pong`.

Наличие Python и uv на компьютере для запуска через Docker не требуется. Для первоначальной Google OAuth-авторизации нужен uv на Windows: см. [инструкцию](docs/GOOGLE_CALENDAR.md).

## Что запускается

- `db`: PostgreSQL 17, данные в именованном volume `postgres_data`. Порт БД наружу не публикуется.
- `bot`: Python 3.12, зависимости из `uv.lock`, непривилегированный пользователь контейнера.
- Compose дожидается готовности БД. Бот проверяет настройки, применяет миграции Alembic, проверяет подключение и запускает polling.
- Миграции создают таблицы черновиков, истории диалога, настроек и журнала напоминаний.
- Сообщения обрабатываются последовательно. Посторонним пользователям и в группах бот не отвечает.

Один токен должен обслуживаться одним запущенным экземпляром бота. Если для него ранее был настроен webhook, его нужно отключить перед long polling.

## Управление

```powershell
docker compose ps
docker compose logs --tail=50 bot
docker compose restart bot
docker compose down
docker compose up --build -d
```

`docker compose down` сохраняет БД. Опция `-v` удаляет её volume — для обычной остановки её не используйте.

Проверка БД и версии миграции:

```powershell
docker compose exec db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "SELECT version_num FROM alembic_version;"'
```

После `down` и повторного `up` версия должна оставаться актуальной (`0005` для текущей версии).

## Если не запускается

- `docker` не найден: установите Docker Desktop и откройте новый терминал.
- Docker daemon недоступен: дождитесь запуска Docker Desktop.
- Compose просит переменную: заполните обязательное поле в `.env`.
- `Invalid configuration fields`: проверьте перечисленные поля; значение секрета в лог не выводится.
- `TelegramUnauthorizedError`: проверьте токен.
- Конфликт polling: остановите другой экземпляр этого бота или отключите ранее настроенный webhook.
- Бот запущен, но молчит: проверьте `OWNER_TELEGRAM_ID` и пишите в личный чат.
- Изменение `POSTGRES_PASSWORD` в `.env` не меняет пароль уже созданной БД. Для существующего volume используйте прежний пароль или явно смените его в PostgreSQL.

## Локальная разработка

Для редактирования и проверки импортов можно установить uv и выполнить `uv sync --locked`. Основной способ запуска приложения — Docker Compose; прямой локальный запуск потребует отдельно обеспечить доступ к PostgreSQL.

В репозиторий входят `pyproject.toml` и `uv.lock`. `.env`, `.venv`, временные файлы `work/` и OAuth-токены в `secrets/` игнорируются Git и не отправляются в Docker build context.

## Облачная модель

В .env добавьте OPENROUTER_API_KEY и при необходимости OPENROUTER_MODEL=openrouter/free. После изменения выполните docker compose up --build -d. Ключ OpenAI не используется. Работают вопросы «Что у меня завтра?» и уточнения. /reset очищает контекст; перезапуск сохраняет историю в PostgreSQL. /today не расходует квоту модели. Один вопрос обычно требует двух запросов API. Бесплатные модели могут быть недоступны или отвечать с задержкой; автоматического перехода на платную модель нет. Названия и время событий передаются OpenRouter и выбранному им провайдеру, описания и участники не передаются.


## Дополнительные возможности

- [Приглашения по email](docs/INVITATIONS.md): до пяти участников при создании встречи, с отдельным подтверждением отправки.

- [Перенос и удаление встреч](docs/EVENT_CHANGES.md) с проверкой версии события и подтверждением кнопкой.
- [Напоминания](docs/REMINDERS.md) примерно за 15 минут, пока бот запущен.
- [Голосовые сообщения](docs/VOICE.md): русская речь до минуты, локальный Whisper. Текст после распознавания обрабатывается агентом.

Перед первым голосовым сообщением загрузите веса модели (один раз):

```powershell
docker compose run --rm --no-deps bot /app/.venv/bin/python -m app.voice_worker --download
```

Веса сохраняются в volume `whisper_models`. Временное аудио удаляется после обработки.
