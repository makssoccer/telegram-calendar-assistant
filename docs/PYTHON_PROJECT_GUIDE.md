# Проект для разработчика без опыта Python

Руководство на основе кода проекта на 1 октября 2026 года. Дополнение от 2 октября: теперь реализован app/agent.py с облачным OpenRouter, проверкой аргументов инструмента, ограничениями и контекстом; разделы ниже о будущей модели описывают прежний этап. Актуальные команды и настройки смотрите в README.md. Рассчитано на человека, знакомого с Java: объясняет Python через реальные файлы приложения.

## 1. Что читать сначала

Для использования бота достаточно [руководства пользователя](../USER_GUIDE.md). Для разработки читайте код в таком порядке:

1. `app/telegram_bot.py`: найдите короткий обработчик `/ping`.
2. `app/__main__.py`: посмотрите, как создаются и запускаются компоненты.
3. `app/config.py`: откуда берутся настройки.
4. Вернитесь в `app/telegram_bot.py` и разберите `/today`.
5. `app/calendar.py`: чтение событий, OAuth-токен и форматирование.
6. `app/storage.py`, `migrations/`, `compose.yaml`: база и окружение.

Не нужно изучать весь Python перед первым изменением. Сначала проследите один запрос от команды до ответа.

## 2. Что сейчас представляет собой приложение

Это один Python-процесс внутри контейнера `bot`. Он получает сообщения из Telegram через long polling — сам обращается к Telegram за обновлениями. Публичный веб-сервер для этого не нужен.

```text
Telegram → aiogram → проверка владельца → обработчик команды
                                             ↓
                                      CalendarService
                                             ↓
                                      Google Calendar API
                                             ↓
                                   форматирование → Telegram
```

Второй контейнер, `db`, содержит PostgreSQL. Сейчас приложение проверяет подключение и применяет начальную миграцию. Таблиц диалогов и черновиков встреч ещё нет; события читаются напрямую из Google.

ИИ-модель ещё не подключена. Принято направление: сторонняя облачная модель через API. Провайдер пока не выбран. Будущий агентный цикл не следует искать в существующем коде — его предстоит написать.

## 4. Минимум синтаксиса

### Функции, отступы и типы

```python
def greeting(name: str) -> str:
    return f"Привет, {name}!"
```

`def` объявляет функцию. `name: str` — аннотация типа параметра, `-> str` — результата. `f"...{name}..."` подставляет значение в строку. Блок определяется отступом, обычно четырьмя пробелами; фигурные скобки и точка с запятой не нужны.

Аннотации сами по себе не запрещают передать другой тип. Они помогают редактору и отдельным анализаторам. В `Settings` Pydantic дополнительно проверяет данные во время выполнения.

```python
def show(value: str | None = None) -> None:
    if value is None:
        return
    print(value)
```

`str | None` означает строку или отсутствие значения. `= None` задаёт значение по умолчанию. `-> None` означает отсутствие полезного результата.

### Коллекции

```python
event = {"summary": "Встреча", "status": "confirmed"}
events = [event]

title = event.get("summary", "Без названия")
status = event["status"]
```

`dict.get` позволяет указать результат при отсутствии ключа. Обращение через `[]` при отсутствии ключа вызовет `KeyError`.

В проекте Google возвращает события как словари. `list[dict]` — список словарей, `tuple[datetime, datetime]` — пара дат. Распаковка пары:

```python
start, end = day_bounds(now, timezone)
```

### Классы и методы

```python
class CalendarService:
    def __init__(self, calendar_id: str):
        self.calendar_id = calendar_id
```

`__init__` инициализирует объект. В объявлении метода `self` указывается явно, при вызове его передаёт Python. Префикс `_` у `_list_events` обозначает внутренний метод по соглашению, а не защищённый модификатор доступа.

`@property` в `config.py` позволяет обращаться к вычисляемому значению как к полю: `settings.database_url`.

### Импорты

```python
from app.calendar import CalendarService
```

Загрузить `CalendarService` из модуля `app/calendar.py`. Файл `.py` — модуль; каталог `app` с `__init__.py` — пакет проекта. При импорте верхнеуровневый код модуля выполняется, поэтому запуск сервиса не размещают произвольно среди импортов.

### Декораторы

```python
@router.message(Command("ping"))
async def ping(message: Message) -> None:
    await message.answer("pong")
```

Декоратор связывает функцию с командой `/ping`. Здесь он регистрирует обработчик в aiogram. Декоратор — исполняемый механизм Python, а не просто аналог метаданных Java-аннотации.

Обработчики объявлены внутри `create_dispatcher`. Это допустимо: функции могут быть вложенными и использовать параметры внешней функции, например `calendar`.

## 5. Как запускается приложение

Docker запускает:

```text
/app/.venv/bin/python -m app
```

`-m app` означает «выполнить пакет app», поэтому Python открывает `app/__main__.py`.

Далее:

1. `main()` настраивает логирование.
2. `Settings()` читает и проверяет конфигурацию.
3. `migrate()` применяет миграции Alembic.
4. `asyncio.run(run(settings))` запускает асинхронную часть.
5. Создаётся подключение к БД и выполняется `SELECT 1`.
6. Создаются Telegram Bot, CalendarService и Dispatcher.
7. Запускается polling.
8. При остановке закрываются Telegram-сессия и пул БД.

Конструкция в конце файла:

```python
if __name__ == "__main__":
    sys.exit(main())
```

Вызывает `main()` при запуске модуля как программы, но не при обычном импорте. Код завершения 0 означает успех, 1 — ошибку.

## 6. Полный путь команды `/today`

1. Telegram возвращает update библиотеке aiogram.
2. `OwnerOnlyMiddleware` проверяет личный чат и ID отправителя. Если доступ не подходит, обработчик не вызывается.
3. Router выбирает функцию `today` по `Command("today")`.
4. `day_bounds` вычисляет начало и конец сегодняшнего дня в заданном часовом поясе.
5. `await calendar.list_events(start, end)` запрашивает события.
6. CalendarService читает OAuth-файл и при необходимости обновляет токен.
7. Google API запрашивается постранично до отсутствия `nextPageToken`.
8. `format_events` преобразует словари в текст, учитывая события на весь день и длину сообщения.
9. `message.answer` отправляет каждую часть в Telegram.

Ошибка `CalendarError` перехватывается и возвращается пользователю понятным сообщением. Другие ошибки обработки update попадают в общий обработчик, который записывает только имя класса ошибки. Полный traceback сейчас намеренно не выводится, поэтому при диагностике может понадобиться локальная отладка.

## 7. Асинхронность в этом проекте

`async def` создаёт асинхронную функцию. Её вызов возвращает coroutine; выполнение обычно запускается через `await`.

```python
events = await calendar.list_events(start, end)
```

`await` позволяет event loop выполнять другую готовую работу во время ожидания. Это не означает создание отдельного потока для каждой функции.

Google-клиент в проекте синхронный. Чтобы его сетевые вызовы не блокировали event loop, применяется:

```python
return await asyncio.to_thread(self._list_events, start, end)
```

Синхронная функция выполняется в рабочем потоке. HTTP-клиент создаётся внутри вызова и не разделяется между потоками. `asyncio.Lock` последовательно пропускает обращения через экземпляр CalendarService, в том числе обновление файла токена.

В polling установлено `handle_as_tasks=False`: сообщения обрабатываются последовательно. Поэтому `/ping`, пришедший во время долгого `/today`, может ждать окончания его обработки, несмотря на использование asyncio.

Не заменяйте `asyncio.to_thread` прямым блокирующим вызовом внутри обработчика. И не используйте `time.sleep` в асинхронной функции — для паузы есть `await asyncio.sleep(...)`.

## 8. Конфигурация и секреты

`DatabaseSettings` наследуется от Pydantic BaseSettings, а `Settings` — от DatabaseSettings. Поэтому Settings содержит и параметры бота, и параметры БД.

```python
owner_telegram_id: int = Field(gt=0)
```

Поле обязательно, должно преобразоваться в целое число больше нуля. `field_validator` выполняет дополнительные проверки токена и часового пояса.

`SecretStr` скрывает значение при обычном отображении модели. Для передачи настоящего секрета клиенту код вызывает `get_secret_value()`. Это маскировка вывода, не шифрование файла.

При запуске на Windows Pydantic может читать `.env`. В Docker файл `.env` внутрь образа не копируется: Compose читает его с хоста и передаёт перечисленные переменные контейнеру. Переменные окружения имеют приоритет над значениями dotenv.

OAuth хранится в каталоге `secrets`, который подключён к контейнеру. Конфигурация клиента и пользовательский токен — разные файлы. `save_token` пишет временный файл и заменяет основной, уменьшая риск частичной записи.

Чтобы добавить новую настройку для Docker, обычно нужны три изменения: поле в Settings, пример в `.env.example` и передача переменной в `compose.yaml`.

## 9. Даты и время

Используйте `datetime` с часовым поясом и `ZoneInfo`. Дата-время без часового пояса неоднозначна; CalendarService такие границы запроса отклоняет.

```python
from datetime import datetime
from zoneinfo import ZoneInfo

now = datetime.now(ZoneInfo("Europe/Minsk"))
```

Время события Google приходит в `dateTime`, а событие на весь день — в `date`. Для них в форматировании разные ветки. Конец многодневного события Google обозначает исключительную границу.

В `day_bounds` вычисляются две календарные полуночи. Это полезнее предположения, что каждый локальный день всегда равен 24 часам: в других часовых поясах есть переходы летнего времени.

## 10. Зависимости и окружения

`pyproject.toml` описывает проект и допустимые версии библиотек. `uv.lock` фиксирует конкретный набор. `.venv` содержит локальное окружение; его не добавляют в Git.

Windows-окружение `.venv` и Linux-окружение внутри Docker — разные. Их нельзя копировать друг поверх друга.

Из корня проекта:

```powershell
uv sync --locked
uv run python --version
uv run python -m app.google_auth
```

Добавление зависимости, когда она действительно нужна:

```powershell
uv add имя-пакета
```

Это меняет pyproject.toml и uv.lock. После этого пересоберите контейнер. Не редактируйте lockfile вручную.

Ruff, mypy и pytest сейчас не входят в зависимости проекта. Отдельного автоматического набора тестов нет по принятому ограничению MVP. Не рассчитывайте, что команды этих инструментов уже настроены.

## 11. Как сделать первое изменение

Простой пример — поменять текст ответа `/ping`:

1. Откройте `app/telegram_bot.py`.
2. Найдите `await message.answer("pong")`.
3. Измените строку, сохранив отступы.
4. Пересоберите и запустите:

   ```powershell
   docker compose up --build -d
   docker compose logs --tail=30 bot
   ```

5. Отправьте `/ping` в Telegram и проверьте ответ.

Исходники не подключены к контейнеру как live-каталог. Простой restart не переносит изменения Python-файлов в образ — нужна сборка.

### Добавление новой команды

Учебный пример, ещё не реализованный в приложении:

```python
@router.message(Command("about"))
async def about(message: Message) -> None:
    await message.answer("Личный помощник для Google Calendar")
```

Вставляйте его внутри `create_dispatcher`, перед универсальным `@router.message()` обработчиком. Универсальный обработчик ловит оставшиеся сообщения; если поставить его раньше, он может перехватить новую команду. Затем добавьте команду в справку.

Для функции календаря добавляйте логику в CalendarService, а обработчик оставляйте коротким: принять команду, вызвать сервис, сформировать ответ.

## 12. Проверка изменений и отладка

Быстрая проверка синтаксиса:

```powershell
uv run python -m compileall -q app migrations
```

Она не проверяет бизнес-логику, авторизацию и доступность API. После неё проверьте изменённый сценарий в работающем боте.

Полезные команды:

```powershell
docker compose ps
docker compose logs --tail=50 bot
docker compose logs --tail=50 db
docker compose config --quiet
```

В редакторе выберите `.venv\Scripts\python.exe` для подсказок и локальной отладки. Начните с чистой функции `format_events` на вымышленных данных.

Прямой запуск `uv run python -m app` пока не является готовым альтернативным способом запуска всего проекта: имя БД `db` разрешается в Docker-сети, а порт PostgreSQL на Windows не опубликован. Для такой отладки потребуется отдельная настройка доступа. Не запускайте одновременно два polling-процесса с одним токеном.

## 13. База и миграции

`create_async_engine` создаёт SQLAlchemy engine с пулом соединений; `asyncpg` — драйвер PostgreSQL. `async with engine.connect()` освобождает соединение после блока.

Alembic хранит номер применённой миграции в таблице `alembic_version`. Начальная `0001` не создаёт бизнес-таблиц.

При добавлении будущей таблицы создаётся новая миграция с upgrade и downgrade. Не меняйте уже применённую миграцию ради нового изменения схемы. Сейчас `target_metadata=None`, поэтому автоматическое сравнение ORM-моделей со схемой ещё не настроено; миграции потребуют явного описания.

Docker volume хранит БД между обычными остановками. `docker compose down` её сохраняет, `down -v` удаляет. Не используйте удаление volume для исправления обычной ошибки запуска.

## 14. Будущая облачная модель

Планируемая схема:

```text
Сообщение → агентный цикл → API облачной модели
                 ↓ запрос инструмента
          проверка аргументов → CalendarService
                 ↓ результат
             модель → ответ в Telegram
```

Код приложения будет выполнять инструменты и проверять разрешения. Модель будет выбирать действия и формировать ответы. Права записи в календарь будут добавлены отдельно; создание встречи потребует подтверждения пользователя.

До выбора провайдера не нужны локальная модель, Ollama или дополнительные серверы. Изменения этого раздела должны отражать фактическую реализацию, когда она появится.

## 15. Небольшой маршрут изучения

1. Прочитать и изменить обработчик `/ping`: функции, строки, декораторы.
2. Разобрать Settings: типы, наследование, валидация.
3. Проследить `/today`: async/await, исключения, сервис.
4. Разобрать format_events: словари, списки, циклы и даты.
5. Посмотреть запуск Docker: переменные, сборка, volume.
6. Разобрать OAuth: клиент, согласие, access token и refresh token.
7. При подключении модели изучить JSON-схемы инструментов и агентный цикл.

Ориентир: уметь объяснить, откуда поступили данные, какой код их проверил и какой компонент выполняет внешний запрос.
