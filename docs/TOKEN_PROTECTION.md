# Защита ключей и контроль расхода токенов

Руководство для владельца Python-бота. **API-ключ** даёт доступ к сервису. **Токены модели** — единицы текста, которые сервис обрабатывает или генерирует. Для первой задачи важны хранение ключа, доступ к файлам и отзыв ключа у провайдера. Для второй бот проверяет каждый исходящий запрос до отправки в OpenRouter.

## Где хранится ключ OpenRouter

1. Создай отдельный ключ для этого бота и задай ему лимит расходов в аккаунте OpenRouter. Приложение само этот лимит не устанавливает. Отдельный ключ позволяет отозвать доступ бота независимо от других приложений.
2. В каталоге проекта создай файл `secrets/openrouter.key`. Вставь ключ одной строкой через локальный редактор. Ограничь доступ к файлу своей учётной записью и процессом, запускающим бот.
3. В локальном `.env` укажи путь **внутри контейнера**. При переходе с ключа в переменной очисти старое значение, чтобы Docker не передавал вторую копию через окружение.

   ```dotenv
   OPENROUTER_KEY_FILE=/app/secrets/openrouter.key
   OPENROUTER_API_KEY=
   ```

4. Примени настройки из корня проекта.

   ```powershell
   docker compose up -d --force-recreate bot
   ```

Compose подключает локальный каталог `./secrets` как `/app/secrets`. При старте бот читает указанный файл. Если путь задан неверно или файл пуст, запуск завершается ошибкой. Если путь вообще не задан, бот использует `OPENROUTER_API_KEY`. Файлы `.env` и содержимое `secrets/` исключены из Git и контекста сборки Docker. Маскирование значений через `SecretStr` помогает при обычном выводе конфигурации. На диске секреты хранятся открытым текстом, а работающий процесс имеет к ним доступ.

При обращении к модели бот передаёт ключ в заголовке авторизации по HTTPS на фиксированный адрес OpenRouter. Переход по HTTP-перенаправлениям отключён. В документацию, сообщения Telegram, материалы для RAG и команды терминала с сохраняемой историей ключ вставлять не следует. Для диагностики избегай публикации вывода `docker compose config` и `docker inspect`: в нём могут оказаться значения переменных окружения.

## Что происходит при запросе пользователя

Например, владелец пишет «Расскажи про Старый замок».

1. **Вход из Telegram.** Бот проверяет ID владельца и тип чата. До запуска обработчика PostgreSQL регистрирует пару `(bot_id, update_id)`. Одинаковая доставка в пределах семи дней обрабатывается один раз, в том числе после перезапуска. Если бот упал после регистрации, но до ответа, владелец может отправить сообщение заново.
2. **Подготовка контекста.** История ограничена четырьмя парами сообщений и 16 000 символами сериализованного JSON. Рассказчик получает отдельный контекст с вопросом и максимум тремя фрагментами. Локальные embeddings расходуют ресурсы компьютера. Прямая команда `/find` выполняет поиск без обращения к OpenRouter.
3. **Проверка действия.** У одного действия общий бюджет в четыре обращения к модели, включая вложенный вызов рассказчика. Агент ограничивает и число вызовов инструментов. Если модель повторяет тот же инструмент с теми же JSON-аргументами, цикл останавливается до повторного выполнения. Отдельное нажатие кнопки продолжения считается новым действием и учитывается в общих квотах.
4. **Проверка размера и цены.** Результат инструмента для следующего шага ограничен 8 000 байтами. Измеряемый размер JSON запроса вместе со схемами инструментов ограничен 64 000 байтами. Конфигурация принимает `openrouter/free` и идентификаторы с суффиксом `:free`. Бот передаёт нулевую максимальную цену за ввод, вывод и запрос и отключает запасные маршруты провайдеров.
5. **Резервирование в PostgreSQL.** Перед HTTP-вызовом бот получает общую блокировку. Одновременно разрешён один запрос к модели для процессов, использующих эту БД. Пока блокировка занята, второй вызов получает отказ. Бот проверяет квоты и отдельной транзакцией фиксирует резерв. Если проверка или запись в БД не удалась, запрос к модели не отправляется.
6. **Ответ и повторы.** Обычный вызов запрашивает до 1 600 выходных токенов. Для рассказа предел составляет 4 096. При обрыве рассказа по длине разрешена ещё одна попытка до 8 192 токенов, если остался бюджет действия. Таймаут и сетевой сбой сохраняют резерв: провайдер мог уже принять запрос. При непригодном формате рассказа бот может показать уже найденные выдержки.

| Квота | Предел |
|---|---|
| На владельца за скользящую минуту | 8 обращений к модели |
| На приложение за скользящие 24 часа | 100 обращений |
| Общий резерв за те же 24 часа | 1 000 000 расчётных единиц |

Резерв одного обращения равен **размеру сериализованного запроса в байтах плюс запрошенный предел выходных токенов**. Например, запрос размером 5 000 байт с лимитом выхода 1 600 резервирует 6 600 единиц. Короткий ответ не уменьшает резерв задним числом. Фактические токены и расходы смотри в аккаунте провайдера. Это особенно важно при утечке: посторонний может вызвать API напрямую, минуя Telegram, квоты PostgreSQL и настройки цены в боте.

## Что происходит с вопросом вне темы

Перед обычным вызовом OpenRouter бот локально проверяет намерение. Сначала используются правила календаря, прогулок и явных посторонних действий. Для свободных формулировок модель E5 сравнивает вопрос с примерами намерений. Учитывается близость к каждой теме и разница между лучшей поддерживаемой и посторонней темами. Эталоны и пороги находятся в [intent_filter.py](../app/intent_filter.py).

| Сообщение | Результат |
|---|---|
| «Как заменить ремень ГРМ?» | Ответ об области работы бота, без вызова OpenRouter. |
| «Добавь встречу в автосервисе для замены ремня ГРМ» | Допуск к календарному сценарию. |
| «А от вокзала?» после обсуждения прогулки | Допуск с историей диалога. |
| «А завтра?» без контекста | Локальная просьба уточнить задачу. |
| Неуверенное сравнение или недоступность E5 | Бот просит сформулировать задачу подробнее, облачный запрос не выполняется. |

Кнопки, команды и ввод материала внутри /learn обрабатываются своими Telegram-обработчиками. Прямой /find выполняет локальный поиск по каталогу и может показать ближайшие места даже для посторонней темы. В обычном диалоге разрешённые запросы по-прежнему проходят через квоты. Фильтр эвристический: необычные формулировки могут потребовать уточнения, возможны ошибочные допуски.

## Если ключ оказался в чате, логе или Git

1. Сразу отзови скомпрометированный ключ в OpenRouter. Проверь активность и расходы за время возможной утечки.
2. Выпусти новый отдельный ключ с лимитом, замени содержимое локального файла и пересоздай контейнер командой выше. Бот читает ключ при запуске.
3. Удали опубликованную копию. Если секрет попал в коммит, проверь также историю Git и копии репозитория. Добавление файла в `.gitignore` действует на последующие добавления и не отзывает опубликованный ключ.

Если раскрыт токен самого Telegram-бота, перевыпусти его через BotFather и обнови `TELEGRAM_BOT_TOKEN`. Если раскрыт файл OAuth Google Calendar, отзови доступ приложения в Google и заново подключи календарь. Это отдельные учётные данные.
