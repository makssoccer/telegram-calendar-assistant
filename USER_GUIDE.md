# Руководство по приложению

Актуально на 2 октября 2026 года.

## 1. Что это за приложение

Личный Telegram-бот для работы с Google Calendar. Приложение работает на вашем компьютере в Docker, а события получает из Google через выданный вами OAuth-доступ.

Бот: [@maksim_calendar_helper_bot](https://t.me/maksim_calendar_helper_bot).

Папка проекта:

```text
C:\Users\maksim.kudzerka\Documents\ChatGPT\TG-bot-assistent
```

### Уже работает

| Команда | Результат |
|---|---|
| `/start` | Краткое описание и список команд |
| `/help` | Список доступных команд |
| `/ping` | Ответ `pong`: приложение принимает сообщения |
| `/today` | События выбранного Google Calendar за сегодня |

Бот отвечает только владельцу в личном чате. Обычные текстовые вопросы о календаре обрабатывает OpenRouter. Команда /reset очищает историю диалога.

### Пока не реализовано

- Создание напоминаний по обычным сообщениям.
- Создание, изменение и удаление встреч.
- Поиск свободного времени.
- Напоминания и другие сервисы.

Подключён бесплатный OpenRouter (openrouter/free). В .env нужен OPENROUTER_API_KEY. Ключ OpenAI не используется. Названия и время встреч передаются облачному провайдеру для ответа; команда /today работает без модели. /reset очищает контекст в приложении, но не удаляет данные на стороне провайдера.

## 2. Что нужно для работы

- Работающий Docker Desktop с Linux-контейнерами и WSL.
- Интернет для Telegram и Google Calendar.
- Файл `.env` с настройками.
- Авторизация Google в `secrets/google-token.json`.

Компьютер должен быть включён и не находиться в спящем режиме. Когда Docker или компьютер выключен, бот не отвечает. Приложение пока не размещено на отдельном сервере.

Python и зависимости бота находятся в Docker-образе. uv на Windows нужен для первоначальной и повторной авторизации Google и локальной разработки.

## 3. Ежедневное использование

1. Запустите Docker Desktop и дождитесь готовности движка.
2. Откройте PowerShell и перейдите в проект:

   ```powershell
   cd C:\Users\maksim.kudzerka\Documents\ChatGPT\TG-bot-assistent
   ```

3. Запустите контейнеры:

   ```powershell
   docker compose up -d
   ```

4. Откройте бота в Telegram и отправьте `/ping`, затем `/today`.

Существующие контейнеры могут запускаться автоматически вместе с Docker. Повторная команда `up -d` допустима: она приводит проект к запущенному состоянию.

После изменений кода используйте сборку:

```powershell
docker compose up --build -d
```

При первом запуске загрузка образов занимает больше времени.

## 4. Как работает `/today`

Команда показывает события от полуночи сегодняшнего дня до полуночи следующего в часовом поясе `USER_TIMEZONE`. По умолчанию это `Europe/Minsk`.

- Обычные встречи отображаются с временем начала и окончания.
- События на весь день отмечаются «Весь день».
- Если встреч нет, бот пишет «Событий нет».
- Длинное расписание разбивается на несколько сообщений.
- Каждый вызов читает Google Calendar заново; перезапуск после добавления события не нужен.

### Если событие не видно

Проверьте три вещи:

1. **Дата:** событие действительно попадает на сегодня по Минску.
2. **Календарь:** оно создано в календаре, указанном в `GOOGLE_CALENDAR_ID`.
3. **Аккаунт:** при авторизации Google выбран аккаунт с доступом к этому календарю.

Страна в настройках Google Calendar не задаёт часовой пояс. Например, страна может быть «Беларусь», а Primary time zone — New York. Одна и та же встреча вечером в Нью-Йорке может приходиться на следующий день в Минске.

В Google Calendar выберите Settings → Time zone → Primary time zone → Minsk. Это изменит отображение времени. Если сама встреча назначена на неверный момент, отредактируйте дату и время встречи отдельно.

## 5. Настройки `.env`

Открыть файл:

```powershell
notepad .env
```

| Настройка | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен созданного бота из BotFather |
| `OWNER_TELEGRAM_ID` | Числовой ID вашего аккаунта, не ID бота |
| `USER_TIMEZONE` | Часовой пояс, по умолчанию `Europe/Minsk` |
| `GOOGLE_CALENDAR_ID` | `primary` для основного календаря или ID другого календаря |
| `POSTGRES_DB` | Имя БД, по умолчанию `assistant` |
| `POSTGRES_USER` | Пользователь БД, по умолчанию `assistant` |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL |

В Docker Compose адрес БД задан как `db:5432`. Настройки `POSTGRES_HOST` и `POSTGRES_PORT` из `.env` предназначены для локального запуска Python; Compose использует собственные значения.

После изменения настроек выполните:

```powershell
docker compose up -d
```

Обычный `docker compose restart bot` не применяет новые переменные окружения из `.env`.

Не перезаписывайте заполненный `.env` файлом `.env.example`: пример содержит пустые поля. Смена `POSTGRES_PASSWORD` в файле не меняет пароль в уже созданной БД — потребуется отдельно изменить пароль PostgreSQL или вернуть прежнее значение.

## 6. Подключение и повторная авторизация Google

Подробная первоначальная настройка: [GOOGLE_CALENDAR.md](docs/GOOGLE_CALENDAR.md).

В каталоге `secrets` используются два файла:

| Файл | Назначение |
|---|---|
| `google-client.json` | Скачанная конфигурация OAuth-клиента типа Desktop app |
| `google-token.json` | Результат вашего согласия на доступ, создаётся приложением |

Если бот сообщает, что доступ истёк или отозван, выполните из корня проекта:

```powershell
uv sync --locked
uv run python -m app.google_auth
```

В обычном браузере Windows откроется Google. Выберите нужный аккаунт и разрешите чтение событий. Если вкладка не видна, проверьте окна через Alt+Tab. Авторизация ожидает ответ до трёх минут; после таймаута повторите команду.

Успешное сообщение:

```text
Google Calendar connected. You can close this window.
```

После этого отправьте `/today`. Перезапуск не требуется: каталог `secrets` подключён к контейнеру, и бот прочитает обновлённый файл. Не запускайте несколько авторизаций одновременно и не вызывайте `/today` во время замены токена.

Файлы авторизации и `.env` содержат секреты. Они исключены из Git; не отправляйте их в переписку и не публикуйте.

## 7. Управление приложением

Все команды выполняются в папке проекта.

| Действие | Команда |
|---|---|
| Запустить | `docker compose up -d` |
| Собрать после изменений и запустить | `docker compose up --build -d` |
| Посмотреть состояние | `docker compose ps` |
| Последние сообщения бота | `docker compose logs --tail=50 bot` |
| Следить за логами | `docker compose logs -f bot` |
| Логи базы | `docker compose logs --tail=50 db` |
| Перезапустить бота с прежними настройками | `docker compose restart bot` |
| Остановить проект | `docker compose down` |

В режиме просмотра логов Ctrl+C завершает просмотр, но не останавливает контейнеры.

Нормальное состояние: `bot` — Up, `db` — Up (healthy). В логах бота после запуска должны появиться подключение к PostgreSQL и Start polling / Run polling.

`docker compose down` сохраняет данные БД в Docker volume. Не добавляйте `-v` для обычной остановки: эта опция удаляет volume БД. Каталог OAuth на компьютере хранится отдельно от volume.

## 8. Решение проблем

| Симптом | Что проверить |
|---|---|
| `docker` не найден | Открыть новый PowerShell после установки Docker Desktop |
| Docker Engine недоступен | Запустить Docker Desktop, проверить WSL и дождаться готовности |
| Compose требует переменную | Заполнить нужное поле `.env` |
| `Invalid configuration fields` | Исправить перечисленные поля `.env` |
| `TelegramUnauthorizedError` | Проверить токен BotFather |
| Конфликт polling | Оставить один экземпляр приложения для этого токена |
| Бот молчит | Проверить контейнеры, интернет, OWNER_TELEGRAM_ID и личный чат |
| Google ещё не подключён | Пройти OAuth по разделу 6 |
| Доступ Google истёк | Повторить OAuth |
| Google отказал в доступе | Проверить Calendar API, тестового пользователя и разрешения |
| Календарь не найден | Проверить GOOGLE_CALENDAR_ID и доступ Google-аккаунта |
| Сегодня нет событий | Проверить дату, часовой пояс, календарь и аккаунт |
| Запрос обычным текстом не работает | Проверить OPENROUTER_API_KEY, лимиты и доступность OpenRouter; /today работает отдельно |

Если нужна помощь, присылайте текст ошибки или скриншот, скрыв токены. Не публикуйте вывод `docker compose config`: он может содержать подставленные секреты. Для проверки конфигурации без вывода значений используйте `docker compose config --quiet`.

## 10. Текущее состояние и следующий шаг

Запуск Docker, PostgreSQL, авторизация Google и чтение календаря проверены. Пользователь подтвердил, что после исправления часового пояса созданное событие видно через `/today`.

Понимание обычных сообщений подключено. Следующий этап — создание встреч с подтверждением. Контекст ограничен четырьмя парами сообщений и очищается при перезапуске. Один вопрос может расходовать несколько запросов бесплатного тарифа.


## Создание встреч — 02.10.2026

Реализованы prepare_event, проверка будущей даты, черновики в PostgreSQL и кнопки «Создать»/«Отмена». Запись выполняется только после подтверждения владельцем. Google ID сохраняется для повторных попыток без дубликатов. Необходима повторная OAuth-авторизация с calendar.events. Проверка реальной записи выполняется пользователем через кнопку; автоматическая тестовая встреча не создаётся. Пример: «Добавь завтра в 15:00 встречу с командой на час».

## Постоянная история — 05.10.2026

История хранится в PostgreSQL: последние четыре пары сообщений, до 16 000 символов JSON. Она загружается перед каждым запросом и сохраняется после перезапуска. Подготовка черновика, успешное создание и отмена записываются вместе с состоянием черновика в одной транзакции. Повторная обработка подтверждения не дублирует результат. Старые сообщения из оперативной памяти до обновления восстановить нельзя. /reset очищает сохранённую историю, но не удаляет встречи и черновики. После /reset новое нажатие кнопки существующего черновика добавит результат в новую историю. История используется для понимания разговора; актуальное расписание по-прежнему запрашивается у Google. Текст хранится в локальной БД и передаётся облачной модели при последующих запросах.
# Перенос и удаление встреч

Теперь можно написать «Перенеси завтра встречу Проверка бота на 16:00» или
«Отмени завтра встречу Проверка бота». Бот найдёт событие и покажет подтверждение.
Перенос показывает старое и новое время; удаление требует кнопки «Удалить встречу».
При совпадении нескольких событий уточните исходное время. Доступны обычные встречи
без повторений и участников. Подробности: [руководство](docs/EVENT_CHANGES.md).
