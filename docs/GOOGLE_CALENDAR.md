# Подключение Google Calendar

Бот пока запрашивает только чтение событий. Доступ на создание встреч появится отдельным этапом с повторным согласием Google.

## 1. Настройка Google

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) под аккаунтом с нужным календарём.
2. Создайте проект, например `Telegram Calendar Assistant`, и выберите его.
3. В **APIs & Services → Library** найдите **Google Calendar API** и нажмите **Enable**.
4. Откройте **Google Auth Platform**. Если предлагается **Get started**, заполните название приложения и свой email.
5. Для личного Gmail выберите аудиторию **External**. В **Audience → Test users** добавьте свой Google email. Для MVP можно оставить статус **Testing**.
6. В **Data Access** добавьте scope `https://www.googleapis.com/auth/calendar.events`, если экран настройки предлагает выбор scopes.
7. В **Clients → Create client** выберите **Desktop app**, задайте любое имя и создайте клиент.
8. Скачайте JSON клиента и сохраните в папку проекта под именем `secrets/google-client.json`.

Не присылайте JSON или OAuth-токен в чат. Каталог `secrets/` исключён из Git и Docker build context.

Официальная основа настройки: [Google Calendar Python quickstart](https://developers.google.com/workspace/calendar/api/quickstart/python).

## 2. Авторизация на компьютере

В PowerShell из корня проекта:

```powershell
uv sync --locked
uv run python -m app.google_auth
```

Откроется браузер. Выберите аккаунт, добавленный в Test users, и разрешите чтение событий. Авторизация ожидает ответ до трёх минут. После успеха создаётся `secrets/google-token.json`.

Если команда `uv` не найдена в уже открытом терминале, откройте новый или используйте:

```powershell
& "$env:USERPROFILE\.local\bin\uv.exe" run python -m app.google_auth
```

OAuth выполняется на Windows: браузер возвращает результат локальному серверу на случайном порту. Docker использует полученный файл через подключённый каталог. Авторизацию выполняйте при отсутствии активного запроса /today.

## 3. Календарь и запуск

По умолчанию используется основной календарь (`primary`). Для другого календаря добавьте в `.env`:

```dotenv
GOOGLE_CALENDAR_ID=идентификатор_календаря
```

ID находится в Google Calendar → настройки нужного календаря → интеграция календаря. Google-аккаунт должен иметь доступ к нему.

После изменения `.env` или кода:

```powershell
docker compose up --build -d
```

После одной только авторизации перезапуск не требуется: бот читает файл при запросе. Напишите `/today` и сравните расписание с Google Calendar. День определяется настройкой `USER_TIMEZONE`, по умолчанию `Europe/Minsk`.

## Возможные ошибки

- **Access blocked / access_denied:** проверьте, добавлен ли выбранный аккаунт в Test users.
- **API disabled / 403:** включите Calendar API в проекте клиента и проверьте выданные разрешения.
- **Календарь не найден:** проверьте GOOGLE_CALENDAR_ID и доступ аккаунта.
- **Доступ истёк или отозван:** повторите `uv run python -m app.google_auth`.
- **Файл авторизации недоступен:** проверьте доступ контейнера к каталогу secrets; на Linux каталог должен быть доступен пользователю контейнера UID 10001 для записи обновлённого токена.

У External-приложения в статусе Testing refresh token для этого доступа обычно истекает через 7 дней. Для длительного использования настройки публикации OAuth разберём отдельно. [Правила Google OAuth](https://developers.google.com/identity/protocols/oauth2).

## Создание встреч

Для записи требуется повторная авторизация: `uv run python -m app.google_auth`. Разрешите доступ к событиям выбранного календаря. Старый токен только для чтения продолжает работать с /today.

Напишите боту: «Добавь завтра в 15:00 встречу с командой на час». Проверьте дату и время в черновике, затем нажмите «Создать». До нажатия записи нет. Черновик действует 15 минут, хранится в PostgreSQL и переживает перезапуск. После сетевой ошибки повторите нажатие через две минуты: используется тот же ID события. Отмена доступна до начала создания. Повторения, участники и изменение событий пока не поддерживаются.
